# Locus 使用說明

<!-- section: start -->
## 這個工具在做什麼

Locus 回答四個規劃師或專案經理在實際會議中常被問到的問題，每個答案都有可追溯的數字：

1. 首次點火在計畫日達成的機率有多高？計畫需要多少緩衝？
2. 真正驅動點火日期的是什麼？
3. 「乾脆先做 X 去搶時間？」這個提案能搶回多少時間、代價是什麼？
4. 設備最晚什麼時候到、許可最晚什麼時候送件，還能保住目標日？

做法是把整個專案模擬很多次（每一次稱為一次 *iteration*，代表一種可能的未來）。工期、到貨、審查與天候在每次模擬中依電廠檔設定的範圍變動。答案是「在多少比例的未來中成立」，而不是單一日期。

參考電廠是虛構的：通用單軸複循環機組，範圍從第一支基樁到燃氣渦輪首次點火。**所有結果都是展示方法的模擬，不是預測。** 氣象統計來自中央氣象署新屋站（467050）2016–2025 年十年的逐日紀錄，經作者加工計算（資料來源：交通部中央氣象署 CODiS 氣候觀測資料查詢服務，依政府資料開放授權條款第 1 版使用，經作者加工計算）。每一頁都會以小字標註出處與這段說明。

建議從 **Summary** 頁開始：每一頁一個發現，並附上前往該頁的連結。每一頁也都有一個可展開的 **How to read this page**，說明該頁怎麼看。本頁（Guide）最上方的 **English / 中文** 切換，會同時改變說明、各頁說明區塊與指標提示的語言；其餘介面維持英文。

## 設定（左側欄）

改動設定**不會**立即重算。按 **Run** 才會更新所有頁面；在按下之前，按鈕下方會提示設定已變更。

| 設定 | 說明 |
|---|---|
| Plant | 電廠模型檔：作業、到貨、連結與設備屬性。 |
| Rule pack | 某個轄區適用的審查、檢查與許可。 |
| Apply weather to the schedule | **預設關閉。** 關閉：天氣只顯示為警告（可能的影響），不改變任何日期。開啟：雨和風依天氣參數讓怕天候的作業停工。Late-start cost 頁一律同時顯示兩種模式。 |
| Weather parameters（收合） | 氣象資料表與測站；雨停工門檻（mm/日）；風的警告門檻與停工門檻（10 分鐘平均，m/s）；會真的停工的強風段比例；每次強風停工後的復工準備天數（0–10 天）；陣風因子（只用於顯示，把風速門檻換算成陣風值）。所有選項都由測站紀錄預先算好。每個設定的出處與查證狀態寫在說明提示裡，也列在 Assumptions and sources 頁。 |
| Station | 該資料表中的氣象測站。 |
| Site start (first piling) | 專案第 0 天（第一支基樁）。 |
| Target first-fire date | 要測試的目標點火日，預設等於單點計畫日。 |
| Advanced: Random seed | 固定隨機情境。相同種子永遠得到相同結果。 |
| Advanced: Confidence for latest dates | 「最晚可接受日期」要保護的未來比例（預設 80%）。 |
| Advanced: Late-start experiment | 延後開工實驗要測到幾週。 |
| Weather parameters：Bad weather comes in spells | 開啟：依測站實測的平均連續天數，前一天停工會提高隔天停工的機率。關閉：每天獨立抽樣。兩種設定的停工天數比例相同。 |
| Advanced: Weather stress test | Weather risk 頁測試的強制停工天數（預設 7 天）。 |
| Advanced: Common risks move many items together | 開啟：套用電廠檔中的共同風險，每個風險都可能同時拖慢很多項目。關閉：每個工期各自獨立變動。不論開關，Common risks 頁都會顯示它們的影響。 |
| Iterations | 模擬次數。日常使用 1,000 次足夠；要對外發表的圖表用 5,000 次。 |

## Summary（總覽）

兩分鐘看完的頁面。每張卡片用一句話加一個關鍵數字說明一個發現，並連到解釋它的頁面：

- **How likely is the plan date?** 單點計畫成立的機率、延誤的最大原因，以及達到 P80 所需的緩衝。
- **What drives the date?** 最常驅動首次點火的項目或串聯鏈，以及驅動路徑上不能打破的連結比例。
- **What do common risks cost?** 會同時拖慢很多項目的風險讓 P80 延後幾天，以及消除影響最大的那一個能搶回多少。
- **Can we win time back?** 效果最好的單一提案，與所有提案一起執行的效果比較。
- **What is already too late?** 相對最晚可接受日期，餘裕最少的外部輸入或審查。
- **A late start, without and with weather**（第一張卡片，也是主要發現）：晚開工四週時，不套用天氣與套用天氣，首次點火各延後多少。兩者的差距就是天氣帶來的額外代價。
- **Weather warnings：** 預計工期內最容易受天氣影響的作業（吊裝看強風、土木看大雨），以及天氣目前有沒有套用到排程。
- **What if bad weather stops the site?** 所有怕天候的作業被強制停工時，從哪一天開始停工對首次點火的影響最大。

這些發現是展示方法的模擬，不是預測。

## Milestone confidence（里程碑信心）

**問題：** 首次點火在計畫日達成的機率有多高？計畫需要多少緩衝？

**數字怎麼來。** *單點計畫* 用最可能工期、設備依計畫日到貨、平均天候算出，也就是一般 P6 排程產生單一日期的做法。模擬則用同一個網圖跑很多次，工期、到貨、審查與天候都從各自的範圍中抽樣。

**畫面上的意義。**

- **Chance of meeting the plan / target：** 在該日期當天或之前首次點火的模擬比例；下方小字是對應的模擬次數。0% 是真實結果而非錯誤：單一數字計畫需要每一項同時都以最可能工期完成。目標日預設等於計畫日，要在側欄設定不同的 **Target first-fire date**，才會另外顯示達成目標日的機率。
- **P50 / P80：** 50% / 80% 的模擬結果會在這天之前首次點火。
- **所需緩衝：** P80 減去計畫日。
- **曲線：** 每個日期之前已首次點火的未來比例。垂直線標示計畫日（與目標日）、P50、P80。

**計畫為什麼會落空（長條圖）。** 單一數字計畫同時假設了四個最好的情況。圖表依下列順序一次拿掉一個，顯示每一步讓首次點火往後移多少天：

1. **Deliveries arrive late（設備晚到）。** 計畫假設每批設備都在計畫日到貨，但延誤範圍從 0 開始：設備只會晚到，不會早到。這一步把每批到貨改成計畫日加上平均延誤。
2. **Durations skew late（工期偏向延後）。** 計畫用最可能工期，但超支的幅度可以比提早的幅度大（例如 60 / 75 / 100 天：最可能 75 天，平均 78 天）。這一步把每項工期改成平均值。
3. **Merge bias（匯流偏差）。** 做完前兩步，仍是用「平均路徑」算出的單一日期。模擬則是在每個未來取匯流路徑中「最晚」的那一條再平均，結果會更晚：首次點火要等剛好晚到的那條路徑。開啟天氣時，這一步也包含天氣的日間變異（計畫只用平均停工損失）。
4. **Common risks（共同風險）。** 會同時拖慢多項工作的事件，單一數字計畫不包含它們。

四步加起來，就是從計畫日到 **模擬平均值**（灰色）。**Spread up to P80**（淺藍）是從平均值再往後、涵蓋八成未來所需的天數；**P80: contingency needed**（深色）是總緩衝。每一步都用同一組亂數計算，加總完全相等；天數先把累積值四捨五入再相減，所以畫面上各步驟加起來一定等於總數。各步驟之間會互相影響，換一個順序，天數會在步驟之間移動幾天，但總數不變。圖下方的展開區說明每一步的意義，以及規劃人員能採取的行動。共同風險這一步量的是風險讓「平均值」移動多少；Common risks 頁報告的是風險讓「P80」移動多少，後者較大，因為風險也會拉寬結果的分布。

這也是「達成計畫的機率」可能是 0% 的原因：計畫需要這四個最好的情況在同一個未來同時發生，工作項目有幾十項時，幾乎不可能。

這些結果是展示方法的模擬，不是預測。

## What drives the date（什麼在驅動日期）

**問題：** 真正驅動首次點火的是什麼？

**數字怎麼來。** 每一次模擬中，模型從首次點火往回追溯，每一步都找出「實際決定這個項目開始時間」的前置項目，形成該次模擬的 *驅動路徑*。一個項目的 **Criticality Index** 就是它出現在驅動路徑上的模擬比例。和單一要徑不同，它能呈現要徑在不同未來之間會移動。

**畫面上的意義。**

- **長條：** Criticality Index 由高到低，最多十列。顏色代表不確定性類型（天候、產能、供應、審查或許可）。
- **合併列：** 永遠一起出現在驅動路徑上的項目（例如基樁、基礎、鋼構這種串聯鏈）合成一列，標示為「第一項 … 最後一項（n items）」。
- **點擊長條**（或在圖下方選擇項目）可看它在等什麼：每個前置項目、連結類型、邏輯關係、連結存在的原因，以及該連結實際驅動它的比例。
- **What the driving path is made of：** 驅動路徑上各類型連結的比例。**斜線長條** 是不能打破的連結（物理、法規）。比例越高，現場靠調整順序搶回時間的空間越小。
- **折疊區：** 依區域與關卡顯示風險集中處的圖，以及列出所有項目的表格。

這些結果是展示方法的模擬，不是預測。

## Common risks（共同風險）

**問題：** 哪一個會同時影響很多項目的風險代價最大？把它消除值多少？

**為什麼重要。** 每個作業的工期範圍是各自獨立抽樣的，所以在同一個未來裡，有些項目延誤、有些提早，大部分會互相抵消。但實際專案還有*共同風險*：一個事件同時拖慢很多項目。缺工會讓所有施工班組一起變慢；航運中斷會讓所有主要設備一起延後到貨。這些延誤不會抵消，所以沒有建模時，P80、P90 會過於樂觀。

**數字怎麼來。** 電廠檔中的每個共同風險都有：

- **發生機率：** 在一個未來中發生的機率（例如 50%）。
- **發生時的大小：** 工期倍數（× 1.00 到 1.25，最可能 1.08），或加在工期或到貨日上的天數。
- **影響範圍：** 受影響的項目，依區域、不確定性類型、種類或代號指定。

每個未來中，風險要嘛發生、要嘛不發生；一旦發生，**所有受影響的項目都套用同一個大小**。正是這個共用的抽樣讓它們的延誤一起變動。同一個項目受到多個風險時，倍數相乘、天數相加。

**畫面上的意義。** 每個數字都是用同一組模擬未來，把風險關掉或打開後重跑得到的：

- **P80 gain if removed：** 消除這個風險、其他風險仍在時，P80 首次點火能提早幾天。這就是減輕或轉嫁這個風險的價值。
- **P80 added on its own：** 只有這一個共同風險時，它讓 P80 延後幾天。
- 兩者不同，而且加總都不等於總和，因為風險之間會互相影響：延誤只有在它所在的路徑驅動首次點火時才有代價。
- **All common risks：** 總影響。只會造成延誤的風險不只影響 P80，也會讓 P50 延後：它們同時增加預期延誤與變異。

**避免重複計算。** 作業的工期範圍應該描述「沒有共同風險時」工作的變動。如果範圍本身已經考慮了缺工，生產力風險就會把它再算一次。

內附的風險是用來展示方法的示意假設（C 級），不是實際專案的估計。

<!-- section: recovery -->
## Win time back（搶回時間）

**問題：** 「乾脆先做 X 去搶時間？」每個提案能搶回多少時間、代價是什麼？

**數字怎麼來。** 每個 *提案* 打破一條軟性連結（現場、合約或改變手段可以調整的連結），然後用 **同一組** 模擬未來重跑。因為隨機抽樣完全相同（*common random numbers*），差異只來自邏輯的改變。

**畫面上的意義。**

- **Drives first fire today：** 改變之前，這條連結位於驅動路徑上的模擬比例。很少驅動點火的連結，打破了也搶不回多少，因為另一條路徑會接手。
- **P50 gain (days)：** P50 首次點火提前幾天。
- **Change in chance：** 達成目標日機率的變化，單位是百分點。
- **Cost or risk：** 打破這條連結的代價。打破連結是用另一種風險換取時程風險，兩者都會列出。
- **Tested, no measurable effect：** P50 移動不到半天、且機率變化不到 0.1 個百分點的提案。這個結果本身也有用：它們的代價目前換不到任何時間。
- **All proposals together：** 所有提案同時執行。通常比最好的單一提案搶回更多，因為縮短一條路徑後，下一條會接手成為瓶頸；搶回時間需要組合，代價也會累加。如果連組合都搶不回多少，槓桿就不在現場邏輯，請到最晚日期頁看外部輸入。

這些結果是展示方法的模擬，不是預測。

## Reviews and latest dates（審查與最晚日期）

**問題：** 哪些審查適用？設備最晚何時到、申請最晚何時送？

**數字怎麼來。** 規則包讀取每項設備的屬性（例如 3 噸以上的固定式起重機），插入適用的審查，並附上法規依據。接著從目標日做反推（backward pass），在每次模擬中算出每個項目最晚可以在何時完成，而不會讓首次點火晚於目標日。

**畫面上的意義。**

- **Latest acceptable date（最晚可接受日期）：** 在所選的未來比例中（預設 80%）仍能保住目標日的最晚完成日，其他項目維持模擬結果。對到貨而言是最晚到貨日；對有計畫送件日的審查而言是最晚送件日（最晚完成日減去 P80 審查時間）；其他審查則是最晚完成日。
- **Planned or expected：** 計畫到貨或送件日；其他審查則是模擬的 P50 完成日。
- **Margin（餘裕）：** 最晚日期減去計畫或預期日期。**負數（紅線）代表目前的安排已經來不及** 達成目標日。
- **等級「A/C」：** 流程等級 / 工期等級。例如流程來自法規條文（A），工期是實務估計（C）。
- **Which reviews apply, and why：** 規則清單。待驗證的規則只列出，不會插入網圖。

注意：目標日預設等於單點計畫日，而很少有模擬能達到，所以預設情況下很多餘裕是負的。可以移動目標日來測試承諾日期。

這些結果是展示方法的模擬，不是預測。

<!-- section: late_start -->
## Late-start cost（延後開工的代價）

**問題：** 開工延後，首次點火是否也延後同樣天數？天氣會多加多少？

**數字怎麼來。** 所有開工類作業延後指定週數，設備到貨與日曆不變。每種延後情境都用同一組模擬未來重跑**兩次**：一次不套用天氣，一次依天氣參數套用天氣。不論開關設定為何，本頁都同時顯示兩者，因為兩者的差距就是主要發現。

**畫面上的意義。**

- **虛線：** 延誤一比一傳遞。
- **灰線（不套用天氣）：** 永遠不會高於虛線。工期固定時，延誤最多一比一傳遞，其他路徑的浮時會吸收一部分。
- **藍線（套用天氣）：** 開工延後會把怕天候的作業移到別的月份。那些月份天氣較差時（吊裝遇上季風、土木遇上梅雨），首次點火延後更多；線若高於虛線，代表延誤被放大。
- **標題數字：** 晚開工四週時，不套用與套用天氣的 P50 延後天數。

結果取決於氣象資料和天氣參數。這是模擬，不是預測。

<!-- section: weather -->
## Weather risk（天候風險）

**問題：** 如果壞天氣讓工地停工一週會怎樣？壞天氣會連續出現，這件事重要嗎？

**停工曲線。** 從某一天開始，在模擬天候之外，再強制所有怕天候的作業停工指定天數（預設 7 天，可在 Advanced 調整），然後用同一組模擬未來重跑。停工起始日每兩週測一次，涵蓋怕天候作業進行的整段期間。

- **接近零：** 當時進行的作業有浮時，或根本沒有怕天候的作業在進行。那段期間停工一週不影響點火。
- **接近虛線：** 當時進行的作業正在驅動首次點火，停工天數直接傳遞過去。
- **不會剛好等於停工天數：** 停工期間原本就會因天候損失的日子不會多扣；損失的可施工日要在之後補回，而補回時的天候是隨機的，所以單一未來的延誤可能多於或少於停工天數。
- **Futures delayed：** 首次點火有被延後的未來比例。

**警告與開關。** 每一頁都會以小字標註天氣是否已套用到排程。開關關閉時（預設），下面的表格**只是警告**：顯示各作業可能遇到的天氣，不改變任何日期。開關開啟時，雨量門檻和風的停工門檻會把這些日子變成停工日。

**雨和風。** *雨：* 日雨量達到門檻（預設 10 mm）的日子，怕雨的作業停工。在參考電廠裡，怕雨的是土木與戶外作業（基樁、基礎、隧道）。建物外殼封閉後，室內工作可以繼續，所以不算怕雨；實際工地通常如此，但不是絕對。

*風：* 強風不一定會讓工作停下來，所以設兩個門檻。達到**警告門檻**（預設 10 m/s）只標示警告；達到**停工門檻**（預設 16 m/s）才會讓怕風的吊裝停工，而且只在套用天氣時生效。警告表列出每一項怕風的吊裝作業（汽機廠房鋼構、屋頂與外牆、管架，以及 HRSG 重吊：外殼、模組、Piggyback 副面板、汽鼓與鋼構），包括它的 P50 施工期間、其中落在東北季風期（10 月到 3 月）的天數，以及預期達到各門檻的天數。套用天氣時，「會真的停工的強風段比例」和每次停工後的「復工準備天數」（0–10 天）決定停工的代價。連續天數（含與不含復工準備）都來自測站紀錄。門檻以測站風速計（離地約 10 m）的 10 分鐘平均風速為準：吊車作業高度的風更強，而且部分每日最大值發生在夜間。陣風因子只用來把門檻換算成陣風值顯示。兩個風速門檻的法源仍待確認。

**連續壞天氣。** 若每天獨立抽樣，幾乎不會出現整週停工（停工比例 25% 時，連續 7 天停工的機率是 0.25⁷，約一萬六千分之一）。實際天氣是一段一段來的：梅雨鋒面或東北季風一來就是好幾天。氣象資料可以為每個月設定**平均連續天數**，也就是連續停工日的平均長度。模型因此改用兩狀態鏈：當天是否停工取決於前一天是否停工，機率經過調整，讓長期停工比例剛好等於資料表的數值。連續天氣不會增加停工天數，只會把停工日集中成一段一段。

比較表用同一組未來分別以「每天獨立」和「連續天氣」重跑。每天獨立時幾乎不可能出現的整週停工，在連續天氣下變得可能，每月停工天數的變異也會變大。不論開關設定為何，這個比較一律套用天氣。P80 會移動多少取決於電廠本身：長工期的怕天候作業會把連續天氣平均掉，有浮時的作業則能吸收。停工曲線顯示停工一週真正有影響的時段。

這些結果是展示方法的模擬，不是預測。

## 名詞解釋

- **Iteration（模擬次數）：** 整個專案的一種模擬未來。
- **Driving path（驅動路徑）：** 在一次模擬中，從首次點火往回追溯、每一步經過「實際決定開始時間」的前置項目所形成的鏈。
- **Criticality Index：** 項目位於驅動路徑上的模擬比例。
- **硬性連結（不能打破）：** *Physical（物理）*：因果關係（沒有冷卻水就沒有真空）。*Regulatory（法規）*：法律或電網調度要求；準備工作可以提早，但步驟本身不能省略。
- **軟性連結（可付出代價打破）：** *Means can change（手段可換）*：需求不變但手段可以換（用臨時重吊取代已檢查合格的天車）。*Contractual（合約）*：雙方約定，可協商。*Resource or sequence（資源或順序）*：班組、順序或施工習慣的選擇。*Logistics or access（物流或動線）*：空間、通道、吊車站位、運輸路線。
- **Merge bias（匯流偏差）：** 首次點火要等多條匯流路徑中最晚的一條，所以它的日期會晚於任何單一路徑的最可能日期。
- **Common random numbers（共同隨機數）：** 所有情境重複使用同一組隨機抽樣，所以情境間的差異只來自邏輯改變。
- **Spell（連續壞天氣）：** 連續因天候停工的一段日子。平均連續天數是這些段落的平均長度；每天獨立時等於 1 / (1 − 停工比例)。
- **Weather switch（天氣開關）：** *Apply weather to the schedule*。關閉（預設）：天氣只顯示為警告。開啟：雨和風依天氣參數讓怕天候的作業停工。
- **Warning and stoppage thresholds（警告門檻與停工門檻）：** 風速達到警告門檻只標示警告；達到停工門檻時，在套用天氣的情況下，怕風的吊裝停工。
- **Remobilisation days（復工準備天數）：** 強風停工後重新開工所需的天數（重新掛索、檢查、人員回到吊裝位置）。
- **Stoppage test（停工壓力測試）：** 在模擬天候之外，強制某段期間所有怕天候作業都不能施工，看停工一週在排程的不同時點代價多大。
- **Common risk（共同風險，risk driver）：** 一個事件一旦發生，就用同一個倍數或天數同時拖慢很多項目，讓它們的延誤一起變動，而不是互相抵消。
- **已知限制：** 除了天候與電廠檔列出的共同風險之外，各作業工期彼此獨立抽樣。沒有被任何風險涵蓋的相依性不會被建模。
